# Docker
Docker – это платформа которая предназначена для разработки, развёртывания и запуска приложений в контейнерах. 
Контейнер:
1.	 В нём можно хранить всё. Может находится либо в контейнере, либо за его пределами
2.	Контейнеры можно переносить. Контейнер и докер можно использовать на локальном компьютере, компьютере в сети, на сервере поставщика облачных услуг (AWS, Azure)
3.	В контейнер удобно что-то класть и удобно что-то вынимать.
4.	Готовые образы контейнеров можно скачать на Docker cloud.


Контейнеры докер потребляют меньше рес-ов по сравнению с VM, так же они быстрее запускаются и приходят в работоспособное состояние.
Образы контейнеров docker – неизменные шаблоны, который используется для создания одинаковых контейнеров. В образе контейнера докер содержится образ базовой ОС, код приложения, библиотеки, конфигурационные файлы. Всё это скомпоновано в виде единой сущности, на основе которой можно создать контейнер.
Docker-файл – содержит набор инструкций, следуя которым, докер будет собирать образ контейнера.
Ключевые особенности и характеристики образа: 
1.	Неизменяемость (нельзя изменить после создания, если нужно внести правку, создание нового образа) Гарантия предсказуемости и повторяемости. 
2.	Многослойность – образ состоит из слоёв, каждая команда при его сборке создаёт новый слой. Это экономит место, если у нескольких образов общие базовые слои, они хранятся на диске в одном экземпляре. 
3.	Содержит всю среду. В отличии от просто архива с кодом, образ содержит абсолютно всё, вплоть до версии системной библиотеки. Это и есть та самая «упаковка» которая гарантирует, что приложение запуститься где угодно


Контейнер - это запущенный изолированный процесс в ОС созданный на основе образа. Контейнеру поверх основных слоев образа добавляется тонки читаемый записываемый слой.

Ключевые характеристики контейнеров: 
1.	Изоляция - контейнер изолирован от хост системы и др контейнеров с с помощью механизма ядра линукс (Namespace, CGroups)
2.	Временность (Эфемерность) – данные созданные внутри контейнера (файлы или бд) по умолчанию живут только пока жив контейнер. При перезагрузке чистый образ, как исходник.


Легковесность – тк контейнеры используют ядро хоста, а не свою ос, они запускаются за секунды и потребляют минимум ресурсов.
Базовые инструкции: 
1.	_FROM_ — задаёт базовый (родительский) образ. Основа образа. 
2.	_COPY / ADD_ — копирует в контейнер файлы и папки.
3.	_CMD_ — задаёт команду с аргументами, которую нужно выполнить когда контейнер будет запущен. Аргументы могут быть переопределены при запуске контейнера. В файле может присутствовать лишь одна инструкция CMD


DockerHub (реестр) – сервис для хранения и распространения образов.


Итоговая схема:
1.	Разраб пишет код приложения и создаёт Docker-файл
2.	Docker build – читает докер-файл и создаёт образ
3.	Образ загружается в реестр
4.	На любом другом сервере этот образ скачивается из реестра 
5.	Команда Docker Run создаёт и запускает контейнер из этого образа


Заключение: Образ – шаблон, реестр – библиотека хз крч чет там
